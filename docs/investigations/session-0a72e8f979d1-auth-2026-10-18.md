## Billing-source policy and limits

| Observed condition | Behavior |
| --- | --- |
| Valid subscription and configured backup key | Subscription first; storing the key does not log out |
| Explicit authentication failure, expired/inactive subscription or entitlement | At most one API fallback for that request, before meaningful output |
| Explicit unsupported-model code | Fallback for that model only |
| Explicit usage/quota exhaustion code | API fallback, with notice and `auth-fallback` decision-log entry |
| Generic429, RPM/TPM throttling or `slow_down` | Preserve the usual retry/backoff path; no billing-source switch |
| Network failure, cancellation, ambiguous403/404, content policy rejection | No inferred API fallback |
| Error after text, reasoning or tool output began | No fallback replay of partial output or tools |
| No configured API backup | Surface the original subscription failure |
| Backup API also fails | Surface that failure; do not loop between credentials |

The fallback latch is local to the provider factory. Auth/entitlement/quota failures affect that provider; model-support failures affect only that model. Credential/login rewarm or process restart creates a fresh primary selection. No automatic periodic subscription re-probing was added. OAuth refresh already occurs during credential initialization.

Recognized error codes are explicit fixture-covered contracts, not a claim that every provider emits every code. An unrecognized response remains an error rather than silently changing billing source. Official OpenAI documentation distinguishes subscription/API authentication and billing, and ordinary rate limiting from credit exhaustion: [authentication](https://learn.chatgpt.com/docs/auth), [API errors](https://developers.openai.com/api/docs/guides/error-codes).

## Corrected experiment side effect

The first compiled probe scripts set private homes/env files but omitted `NODE_ENV=test`. `persistEnvVar` also mirrors credentials into Windows User environment; the private home alone did not isolate that write. Those runs temporarily replaced the User-scope DeepSeek/OpenAI values with synthetic fixture keys. The original incident's 07:34Z failures predate these 08:04–08:10Z experiments.

The repair checked for exact fixture values before changing anything. DeepSeek was restored from the unchanged canonical CLI `.env` store; OpenAI's introduced fixture value was removed because that store contained no OpenAI API key. The restored environment was broadcast to Windows. Neither genuine CLI `.env` nor OAuth token files were rewritten. There was no pre-experiment registry snapshot, so this is a canonical-store repair, not proof of byte-identical restoration of any earlier OS-only value. See `registry-repair.json`.

Both compiled probes now set `NODE_ENV=test` before credential writes. A new wrapper snapshots the two User variables in memory, runs both probes and compares them afterward without printing secrets. Final rerun: both exits0, `registryUnchanged=true`. Existing registry-guard tests plus the credential-refresh tests passed8/8. These follow-up tests overlap the focused suite; do not sum the counts as unique coverage.
