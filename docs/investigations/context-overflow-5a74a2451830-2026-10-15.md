## Failure path

1. The main called `search_session_history` with `query="recent session"`. The implementation selected fifty FTS rows and serialized complete `content`, `tool_args`, and `tool_output` fields. Historical tool outputs included earlier history-search results, amplifying the payload.
2. Main assistant message sequence 5 mentioned `PRESERVE_FULL_CONTEXT` in an explanation. The old prepareStep logic searched all historical messages for the substring, including explanatory mentions and tool/user content, and returned before compaction. This older mention affected a later user turn.
3. `estimateMessageTokens` reused the summarizer's text extraction. That extraction shortened each tool result to 8,000 characters before token counting. Consequently post-turn sizing did not account for the full data actually sent.
4. The final model gate correctly recorded excessive size but was configured as a meter in warn mode. Its rough chars/4 metering contract intentionally did not reject the request. There was no independent prepared-request guard to protect the physical model window.

## Changes

- History search now returns bounded, valid JSON excerpts. Each result retains session/sequence identifiers and original lengths for truncated fields. The response reports selected and returned match counts, omissions, and `next_offset`; offset pagination avoids resending all results. Search remains global as before: this change does not introduce session/project filtering. Full fields remain in the source DB, and omitted excerpt content requires a narrower query.
- Context sizing counts full structured textual messages, tool arguments, results and reasoning. Summarizer previews remain bounded independently. Binary image/file data is excluded from text tokenization.
- Only standalone assistant preservation directives in the active user turn affect compaction. Old turns, explanatory mentions and text returned by tools cannot create a persistent veto.
- Main and child paths check the prepared textual request estimate, including system, resolved tool schemas and reserved completion, against the catalog window. Preservation does not bypass this check. If the request still exceeds the estimated budget, it is rejected locally and directed toward compaction/narrower retrieval. Existing model-gate metering and account rate-limit policies remain unchanged.

Token estimates use the existing proxy tokenizer. They are not exact StepFun token counts and cannot guarantee that every provider-specific media/framing combination fits. The observed oversized textual payload is detected by the new check.
